# QC-067 驗收記錄（前端）：作品庫超過 200 件的分頁

日期：2026-11-22　分支：`feat/qc067-library-paging`，基於 main `c9a1c4d`（已含 QC-067 後端 `8b7928e`：分頁、facets、refs、`sole_count`）。

## 問題

`LibraryPage.tsx` 只呼叫一次 `works.list({ limit: 200 })`，於是：

- 作品超過 200 件時，較舊的作品從作品庫消失（資料還在）；
- 類型和狀態的數量，只算已載入的那 200 件；
- ⌘A 只選得到已載入的作品。

最近刪除和平台預覽的作品選單也一樣只讀 200 件；刪除項目對話框裡「會移到未分類」的數量，同樣只看 200 件。

## 做了什麼

- **分頁讀取**（`library-feed.ts`）：
  - 服務端 cursor 分頁，一頁 60 件。
  - 清單末端的 `LoadMore` 在接近畫面時（提早約一個畫面）載入下一頁；載入失敗時顯示「重試」，按下後從頭重讀（cursor 過期也一樣）。
  - 晚到的、屬於舊篩選的頁會被丟掉。
  - 捲動時作品被更新而換了位置，也不會重複出現。
- **即時更新**：SSE 變更時從頭重讀到目前已載入的深度，捲到的位置和已顯示的作品都保留。
- **篩選與數量**：
  - 類型和狀態篩選交給服務端處理。
  - 數量來自 `GET /works/facets` 的總數：類型 chip 是各類型的總數，狀態 chip 是目前所選類型下各狀態的總數。
  - 標題旁的數字是整個篩選的總數。
- **⌘A 的範圍**：
  - **目前篩選下的全部作品**，不只已載入的。用 `GET /works/refs` 取得；工具列顯示「已選 N 個」。
  - 右鍵已選的作品、批量改狀態、加減標籤、加入或移出項目、刪除，都作用在這全部 N 個上。批次仍是每次 200 件，前端分批送。
  - ⇧ 點擊（換成一個範圍）、Esc、換篩選，都會結束全選；⌘ 點擊只增減一件，全選的其他作品仍在。
- **最近刪除**：同樣分頁；⌘A 選取全部刪除的作品，還原和永久刪除也作用在全部。
- **平台預覽的作品選單**：同樣分頁，看得到全部作品。
- **刪除項目對話框**：「其中 N 個會移到未分類」改用 `GET /projects/:id/summary` 的 `sole_count`。前端自己算的 `unsortedAfterRemoving` 已移除。

## 效能

用同一個臨時 spec（未提交），在 main 和這個分支上各量一次：種 320 件作品，重新載入 3 次，量到前 60 張卡片出現所需的時間。

| 版本 | 前 60 張出現（ms，3 次） | 第一次畫出的卡片數 |
| --- | --- | --- |
| main（後端合併前）| 226、185、181 | 200 |
| 這個分支 | 180、155、147 | 60 |

首次顯示更快，畫面上的卡片也少了 70%：之後的頁只在捲到時才載入，每頁 60 張。300 張卡片時的長幀檢查，仍等 qc-test 在打包版上量。

## 測試

- **單元測試**（`library-feed.test.ts`，7 項）：
  - 分頁直到全部載入，沒有更多頁時不再請求；
  - 作品在分頁途中移位時不重複；
  - 換篩選後，晚到的舊頁被丟掉；
  - refresh 重讀到已載入的深度，之後還能繼續往下載；
  - patch 和 remove 會同時更新清單與總數；
  - 失敗後可以重試；
  - facets 加總（缺的組合當 0）。
- **e2e**（`library-paging.spec.ts`，種 180 篇文章加 140 篇貼圖，共 320 件）：
  - 一開始載入 60 件，標題和各個 chip 的數量是總數；
  - 捲到底，320 件全部載入，看得到最舊的「文章 001」；
  - 篩選「貼圖」：數量 140，捲到底是全部 140 件；
  - 篩選「文章」後 ⌘A：已選 180 個，批量改成「待審核」，服務端 180 件全改了，chip 數量也跟著更新；
  - 篩選「貼圖」後 ⌘A 再刪除：140 件都進最近刪除；
  - 最近刪除：分頁捲到底是 140 件，⌘A 已選 140 個。

## NOT_VERIFIED

- 規格提到的「虛擬化列表」沒有做，改成捲到底自動載入。已載入的卡片會一直留在 DOM 裡：使用者一路捲過上千件時，卡片數也會跟著變多。真的需要時，可以之後再加虛擬化。
- 全選上限是 10,000 件（`WORK_REFS_MAX`），超過時服務端回 413，前端會顯示錯誤訊息；這個情況沒有寫 e2e。
