## 觀察：第一次改寫被自動重試兩次

`change_log` 中 `635cc25b` 的事件順序：

```
06:39:23 queued → 06:39:23 running → 06:39:26 queued
         → 06:39:31 running → 06:39:36 queued
         → 06:39:46 running → 06:39:52 succeeded
```

- 前兩次執行各約 3–5 秒就結束並重新排隊，間隔 5 秒、10 秒，符合可重試錯誤（限流、逾時、上游故障）的指數退避（`retryBaseMs` 5000）。第三次成功。
- **重試原因無法追查**：成功後 `error_code` 清空，服務日誌也沒有記錄可重試的供應商錯誤（沒有 warn）。
