# QC-073 驗收記錄：動效開啟時的 7 個 e2e 失敗（阻擋發版）

日期：2026-11-22　分支：`fix/qc073-motion-layers`，基於 main `430c467`。

實際的 App 預設開著動效，所以這 7 個失敗都當成使用者會碰到的缺陷處理，包括上一版（18dff82）就已經存在的 4 個。每一個都先查到根因再修，修在出問題的地方。沒有加長逾時、沒有加重試，也沒有放寬斷言。

## 根因與修正

### 1. 淡出中的靜態副本，還被當成「開著的對話框或選單」

影響 4 個測試：

- library-actions 的「⌘A 全選」（⌘A 沒有反應）；
- library-actions 的「⌘⌫ 刪除兩個選取的作品」（⌘⌫ 沒有反應）；
- editor-tabs 的「關閉未存的分頁」（⌘W 沒有反應）；
- ai-image-editor 的「有候選未保留時關閉」（⌘W 沒有反應）。

**根因**：

- 對話框、選單、彈出層關閉時，`useExitFade` 會在原位留下一份靜態副本淡出（`fast`，約 120ms）。
- 這份副本是完整複製的：`role`、`aria-modal="true"`、`.ctx-menu` 都還在。
- 鍵盤處理用 `document.querySelector('[aria-modal="true"], .ctx-menu')` 判斷「有沒有開著的圖層」，所以在副本淡出的那段時間裡，⌘A（作品庫、最近刪除）、⌘⌫、⌘W 都被吞掉。
- 使用者關掉選單或對話框後馬上按快捷鍵，就會碰到。

**修正**：

- `useExitFade` 的副本拿掉 `role`、`aria-modal`（它本來就設了 `aria-hidden`、`inert`），並加上 `data-leaving` 標記。
- 新增 `hasOpenLayer(menus)`（`motion.tsx`），判斷時排除 `[data-leaving]` 的副本。EditorTabs（⌘W）、LibraryPage、LibraryTrash（⌘A、⌘⌫、esc）都改用它。
- 原本各自判斷的範圍不變：⌘W 只看對話框；作品庫看對話框和右鍵選單。
- 側欄過渡的副本也加上 `data-leaving`。

### 2. 批量列的「改狀態」選單一打開就關閉；右鍵選單的子選單打不開

影響 library-paging 的「⌘A 後批量改狀態」。qc-test 也量到：作品超過一頁時，動效開或關都會發生，130 件時 14 次有 11 次關掉（見 `qc070-perf.md`）。

**實測事件順序**：

- 選單打開時，`main.page` 從 0 捲到 72px，觸發一個 capture 階段的 scroll 事件；`ContextMenu` 收到任何 scroll 都會關閉。
- 這 72px 的來源：用原始滑鼠事件，在同樣的 130 件、同樣的位置點擊，連續 5 次，`main.page` 完全沒有捲動，選單也一直開著。
  - 所以捲動不是 App 自己造成的。是 Playwright 點擊前的 scroll-into-view：它總是嘗試捲動，只有頁面捲得動（超過一頁）時才真的發生，所以 40 件時看不到。
  - scroll 事件在捲動後的下一個畫格才派送，這時選單已經打開、掛好監聽，就把剛打開的選單關掉了。
  - 使用者也會碰到同一個時間差：觸控板慣性捲動剛停，馬上點按鈕。

**修正一：選單只因「它來源的區域」捲動而關閉。**

- 選單打開時，記下來源（觸發的控制項，或錨點下的元素）所在的每一層捲動區域和頁面的捲動位置。
- 收到 scroll 時，只有這些位置真的變了才關閉。
- 打開前就結束的捲動、無關區域的捲動（例如別處的清單），都不會關掉它；它指向的東西被捲走時，照樣會關，e2e 有驗證這一點。

**修正二：右鍵選單的子選單被父元件的重新渲染取消。**

- 這是補 130 件的回歸 e2e 時抓到的：右鍵選單的「改狀態 ▸」滑過去打不開。
- 加 log 查到：滑過有觸發，子選單也排好了 120ms 後打開，但從來沒有打開。
- 根因：`close` 依賴宿主每次渲染都會換新的 `onClose`，所以掛監聽的 effect 每次宿主重新渲染就重跑，它的 cleanup 會清掉等著打開子選單的計時器。剛改完狀態、清單被即時更新重新讀取時，正好落在這 120ms 裡。
- 修正：`onClose` 改用 ref 讀取，`close` 保持穩定，監聽和計時器只隨選單本身建立與清除。

### 3. 兩則提示同時出現時互相重疊

影響 image-post 的「兩則提示上下堆疊」。

**根因**（逐幀量測）：

- 新提示出現時，舊提示用 `snappy` 彈簧往上讓位（layout 動畫），但起點是新提示現在佔的位置。
- 新提示只從 8px 下方升起。
- 所以前約 115ms 兩則重疊，最多 31px。

**修正**：

- 堆疊中新加入的提示（`toast` preset 的 `stacked`），改從自身高度的 150% 下方，用同一個 `snappy` 彈簧升起，整疊一起往上移。
- 起點多出的這段，是預留給 layout 動畫晚幾個畫格才開始的情況：第一版用 125% 時，在 load 18 的機器上仍量到 0.38px 的重疊，所以加大到 150%。
- 在一般負載下逐幀量測（用 125% 量了三次），兩則之間的間距一直維持在約 7px 以上，從頭到尾沒有重疊。
- 只有一則提示時照舊輕升；減少動態效果時只淡入。

### 4. 側欄測試：locator 對到過渡副本（測試問題）

影響 sidebar-logo-toggle。

**根因**：QC-068 的側欄過渡會留一份靜態副本，也是 `nav.sb`，所以測試的 `nav.sb .sb__dot` 對到兩個元素。

**修正**：locator 改成 `nav.sb:not(.sb--ghost)`。

**修完之後又抓到一個真缺陷**：

- 同一個測試接著把視窗縮窄，視窗窄時側欄會被強制改成圖示列。這時剛才展開的過渡動畫還在跑，而那段動畫是照舊寬度算的，會把側欄推出畫面外，直到動畫結束。
- 修正：側欄不是因為使用者切換而改變時（例如窄視窗強制圖示列），立刻停掉進行中的過渡（`stopSidebarMorph`）。

## 測試

- 新增回歸 e2e：`library-status-menu.spec.ts`，種 130 件，一般模式與動效模式都要跑：
  - 選取工具列的「改狀態」打開後，等兩個畫格（讓打開前的捲動事件送到）仍然開著，選「待審核」後，兩件都改到；
  - 右鍵選單的「改狀態 ▸ 待發布」，兩件都改到；
  - 右鍵選單打開後，把 `main.page` 捲動 300px，選單會關閉。
- 單元測試，`motion.test.ts`：新增一項，檢查新提示加入堆疊時的 preset：從 150% 下方升起、用 `snappy` 彈簧；只有一則時照舊輕升；減少動態效果時只淡入。
- 判斷開著的圖層、選單的捲動判斷，都需要 DOM。`apps/mac` 的單元測試沒有 DOM 環境，所以這兩項由動效開啟的 e2e 全套守住：library-actions、editor-tabs、library-paging、ai-image-editor 正是踩到這兩個問題的測試。這一輪起，每次交付都要跑這個模式。
- 除錯時用的暫存 spec 和暫時加的量測程式都沒有提交。
